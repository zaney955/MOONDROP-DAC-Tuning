# ECHO-B 固件与恢复

**本仓库没有已验证可用于 ECHO-B `35d8:149b` 的完整固件备份、恢复镜像或救砖工具。** EQ 读回、官方目录候选文件及同代协议代码都不能填补这个缺口。

本页整理截至 2026-10-30 已保存的 APK、公开服务响应、升级文件和源代码分析。固件研究未向设备发送读取、重置或升级请求；下载文件不等于从耳放取得备份。远端目录后续可能变化，结论以所链接快照为依据。

## 升级包兼容性

官方 APK 将 `35d8:149b` 分派到 Freeman3/Synaptics；既有实机帧与 CAPE 协议相符。官方目录名为 ECHO-B、version 为 `1.0.0` 的候选却采用 `SPV@` 格式：

| 核对项 | 保存的分析结果 |
| --- | --- |
| 文件身份 | 442,216 字节；SHA-256 `b68e0cd4a561cb664605f32ebf5d3c3e51f6138482b3bfc97ef9666a42b5acc1` |
| 产品关联 | 按 ECHO-B 产品 UUID 精确查询仍返回此文件；BIANCA 另一 URL 返回逐字节相同内容 |
| 载荷 | 官方 SPV parser 可解释 CPU / MOD 段，CPU 实际传输载荷中有 Marigold USB 字符串描述符 |
| 格式冲突 | 未建立 SPV 文件与 ECHO-B CAPE 更新路径的兼容性 |
| Web 展示 | 保存的网页实现过滤 version=`1.0.0` 条目；不能泛化为 Android 行为或占位证明 |

这些事实削弱目录标签的适配可信度，但不能确定后台关联错误的具体原因，也不能仅凭字符串推断运行时设备身份。该文件不应作为本机恢复镜像。

已保存目录中的六个 `.hid` 候选，目标头分别为 FreeDSP `35d8:1496`、MAY `35d8:1497`、DUSK／DUSK-SP／Starlight `35d8:1499` 和 moca `06cb:1594`，均不匹配 ECHO-B。共享 EQ 协议、修改包头或重命名不能建立固件兼容性。

## CAPE 包与工具边界

CAPE `.hid` 包有 32 字节头，包含 VID、PID、update type、`EFSC` 格式标记、CRC 字段和版本分量。已分析候选载荷为 114,688 字节；载荷长度不等于完整闪存容量。`EFSC` 不是密码学签名，存在 CRC 字段也不代表已经验证载荷。

部分型号共享大段程序代码，但后续配置含不同型号 USB 描述符。升级包因此包含型号相关内容；它仍不证明覆盖 ROM、OTP、引导程序或单机校准。普通 SDK 的 `SFSE` 存储解析也不能直接套用到 `EFSC` 载荷。

Synaptics 编写的 [fwupd CAPE 插件](https://github.com/fwupd/fwupd/tree/2796458862b73aa541ee1786bf73c9cb7d147103/plugins/synaptics-cape)与既有协议布局吻合，但没有 ECHO-B 设备条目或 `read_firmware` 备份钩子。其准备函数假定两份等长分区镜像，不能直接接收这里的单个 `.hid` 文件。正常运行态更新支持也不证明主固件失效后可恢复。另一个 `synaptics-cxaudio` 插件的报告格式不同，不能混用。

## SDK 读取接口的限制

| 路径 | 静态代码观察 | 尚缺证据 |
| --- | --- | --- |
| SPI 读取 | CTRL `0x010e` 设置地址／长度，`0x010d` 取数据；可能先发非 GET 的 `0x000c` 打开事务 | 本机存储布局、容量及设备端状态影响 |
| EEPROM 文件导出 | 查询容量、读取后写文件；20805 分支先执行 `EepromPrepareForPatch`，日志为 `Reset streamer app` | 无状态变化的导出方式、完整恢复区域覆盖 |
| 单 DWORD 内存读取 | GET `0x0106` 返回一个 32 位值 | 有效区域、读保护及完整持久存储映射 |

SDK 有这些函数，不等于它们可直接用于 ECHO-B。CAPE 的 EEPROM 读取实际转向 SPI，名称不证明有独立 EEPROM；ROM 版本字符串也不证明能导出 ROM。SDK 类名和默认芯片码不能替代实物料号鉴定。

官方正常更新链包含 patch、reset 和重新连接，但没有建立 ECHO-B 专属 ROM／bootloader 入口、异常 VID/PID、进入条件或硬件恢复验收。App 硬编码的活动分区字符串 `"2"` 不是双分区读回或回滚保证。

## 建立恢复方案还需要什么

需要明确匹配 USB ID 及硬件版本的厂商镜像／说明，或已核实容量、区域覆盖、重复读取一致性和身份／校准数据保留的本机备份。救砖还需证明失去主固件后的进入方式、匹配工具与刷回验收。

已有公开来源搜索及历史 App 索引未补出匹配镜像；历史下载失败只说明未取得内容，不证明厂商不存在内部镜像。现有证据不足以承诺完整恢复。
