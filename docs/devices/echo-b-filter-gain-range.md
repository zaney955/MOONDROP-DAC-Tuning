# ECHO-B 滤波器增益与系数范围

`gain_db` 使用标准 RBJ 峰值 Q / 架式 S=1 语义，接受按 0.1 dB 步进的有限数值，不设固定上下限。实际可编译范围取决于类型、频率、Q 值和采样率。接口规则见[JSON 格式](../../presets/README.md)。

设备接收五个系数，而非直接按 dB 数值调整滤波器。本工具使用固定 Gain=3 的有符号 24 位 Q22；所有五种采样率都必须通过数值、编码范围和量化稳定性检查。单一采样率的可写入系数不等于整份预设可编译。

## 48 kHz 系数验证示例

以下参数对应的系数具有写入及精确读回证据，右列是相邻整数请求的离线编码结果。它们不是模拟输出测得的增益极限，也不是全采样率通用范围。

| 类型 | 频率 / Hz | Q／S | 已验证请求 / dB | 相邻整数请求 |
| --- | ---: | --- | ---: | --- |
| 峰值 | 1000 | Q=0.1 | +15 | +16 系数溢出 |
| 峰值 | 1000 | Q=1 | +47 | +48 系数溢出 |
| 峰值 | 1000 | Q=10 | +87 | +88 系数溢出 |
| 峰值 | 10000 | Q=1 | +17 | +18 系数溢出 |
| 低架 | 1000 | S=1 | +72 | +73 系数溢出 |
| 高架 | 1000 | S=1 | +0.5 | +1 系数溢出 |
| 低架 | 10000 | S=1 | +14 | +15 系数溢出 |
| 高架 | 10000 | S=1 | +10 | +11 系数溢出 |

+0.5 dB 是系数通道的验证点；日常 JSON 格式现支持 0.1 dB 步进，但尚未新增 0.1 dB 的实机验证。表格不提供整数之间的精确边界。

负向请求 −120 dB 的系数也有读回证据，但它不代表准确调音下限。例如 1 kHz、Q=1 的峰值请求 −120 dB，Q22 模型的中心响应约为 −117.65 dB。合法且稳定的系数不保证量化响应精度或无削波。

## 验证边界与依据

系数通道的验证数据包含 105 组 ACK 与精确读回；66 组离线溢出候选未发送。验证不包含整 dB 参数标签的大范围写入、模拟频响、噪声、失真、保存后断电保持或五种采样率逐项实机行为。

- [案例生成器](../../tools/prepare_filter_gain_probe.py)、[临时探测器](../../tools/echo_filter_probe.c)及[故障注入测试](../../tools/test_echo_filter_probe.c)

探测器须持设备锁运行，要求第 8 段直通、第 9 段为非正纯增益，测试期间通过第 8 段静音。备份和恢复要求见[诊断工具](echo-b-output-gain-range.md#诊断工具)。

官方 App 使用不同滤波公式和动态 Gain 缩放，不能套用固定 Q22 的编码边界，详见[算法兼容性](echo-b-android-eq-comparison.md)。
