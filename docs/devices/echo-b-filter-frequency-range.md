# ECHO-B 滤波器频率范围检查

检查日期：2026-10-30。结论：当前工具支持 **20–20000 Hz、整数 Hz**。这是编辑器及预设编译器明确设置的输入范围，不是已证实的硬件频率极限。范围外部分参数能生成合法系数，但尚无本次实机写入、读回或模拟频响证据。

## 当前限制在哪里

- `tools/preset.py` 的 `compile_preset()` 调用 `number(frequency_hz, 20, 20000)`，并要求整数；超出后在访问设备前拒绝。
- `web/app.js` 对数值输入、滑块、曲线拖动及新建滤波器都有相同边界。只修改 HTML 或 JSON 不能绕过后端校验。
- 曲线预览及编译响应抽样也固定为 20 Hz–20 kHz；扩展输入范围时需要一并处理预览和响应检查覆盖。

频率是峰值的中心频率、架式的增益中点，不能理解为滤波器影响仅限于该频率或 20 Hz–20 kHz 内。定义与公式见 [W3C Audio EQ Cookbook](https://www.w3.org/TR/audio-eq-cookbook/)。

## 离线扩展检查

检查脚本只在独立 Python 进程内临时跳过频率输入上下限，保留实际编译器的系数计算、五采样率检查、编码及响应检查。没有修改正式编译器或发送设备命令。

下表仅适用于 **peak、Q=1、gain_db=−6、output_gain_db=−16**，全采样率为 44.1 / 48 / 96 / 192 / 384 kHz。

| 频率 / Hz | 临时放宽输入范围后的完整编译结果 |
| --- | --- |
| 1 | 44.1 kHz 下量化不稳定 |
| 5 | 192 kHz 下量化不稳定 |
| 10、15 | 384 kHz 下量化不稳定 |
| 19 | 通过 |
| 20、20000 | 通过 |
| 20001、21000、22000、22040 | 通过 |
| 22049 | 44.1 kHz 下量化不稳定 |
| 22050、23000、24000、30000 | 44.1 kHz 下系数超出固定 Q22 范围 |

这些是离散样本，**不是连续可用区间或通用上下限**。最低可用频率和靠近高端的余量取决于类型、Q、增益、采样率及定点量化；稳定且可编码也不证明标称增益精度、模拟输出精度或内部余量。不能用 gain_db=0 的直通特例证明任意中心频率可用。

正常 biquad 中心/转折频率应处于 `0 < f < Fs/2` 内；边界处可能退化，范围外的周期性公式结果不能视为目标频率上的正常滤波。当前工具为五种采样率生成并保存系数，因此若维持这一模型，统一高端必须低于最低采样率对应的 **22050 Hz**，并继续逐项检查量化稳定性和编码范围。48 kHz 的对应边界是 24000 Hz，96 kHz 是 48000 Hz；这不表示当前完整预设能接受这些频率。参考 [Web Audio biquad 频率定义](https://webaudio.github.io/web-audio-api/#dom-biquadfilternode-frequency)及本项目公式。

## 官方计算库与协议不能混为一谈

已有 Java/JNI 证据表明官方原生输入 `Freq_Hz` 为 uint16，即字段编码能表达 0–65535；这不证明 App 界面、原生算法或固件支持全部数值。设备实际滤波写入的是五个系数及缩放值，频率参数标签与实际滤波系数分开传输。见 [输入路径](../../evidence/android-eq-path-notes.md)和[设备协议](echo-b-investigation.md)。

此次使用现有 ARM64 模拟执行器检查官方库，三种滤波器、Q=1、−6 dB 的 **20001 Hz** 样本在五种采样率均返回 0，产生稳定且可编码的系数。因此，该库没有对所有输入实行 20000 Hz 的绝对上限。但例如 peak、Q=1、−6 dB、21000 Hz 在 44.1 / 48 / 96 kHz 返回非零状态；19 Hz 在 384 kHz 也返回非零。Java 包装器遇到非零状态返回 null，不能将这些输出当成官方成功结果。

原生公式入口 `0x31f0–0x31fc` 还检查频率是否达到 `Fs/2`；边界外不进入正常的三角函数设计路径。不能把这个分支或非零返回概括成固件钳制、成功支持或安全绕过。原始指令见 [反汇编](../../evidence/android-eq-comparison-20261030/native-converter.asm)。

模拟器的外部 libm 调用桥接主机 Python 数学函数：此次有 19 个案例产生主机数学异常，这些属于模拟器限制，不能声称观察到了 Android 崩溃或固件行为。所有原始返回码和异常均保留；没有将非零状态输出计作成功。该库与本工具使用的滤波语义也不同，见[算法兼容性](echo-b-android-eq-comparison.md)。

仅复算本工具离线结果（会覆盖该目录下的 results.json，不包含官方模拟结果）：

```sh
PYTHONPATH=tools python3 evidence/filter-frequency-range-20261030/check.py
```

要复算官方模拟结果，在 `PYTHONPATH` 加入现有的 Unicorn / pyelftools 分析依赖目录，并添加 `--official`。此次使用 `/tmp/echo-official-eq-python`；分析环境须允许 Unicorn 缓存初始化。

本次没有放宽正式范围。若后续扩展，应同步修改前后端范围与图表覆盖，强制 `0 < f < Fs/2` 并保留每个采样率的系数及稳定性检查，再单独验证设备接受、读回及实际响应。
