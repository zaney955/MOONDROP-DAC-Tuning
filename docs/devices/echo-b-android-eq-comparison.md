# ECHO-B：官方 Android App 与本工具的同参数系数对比

调查日期：2026-10-30。**结论：同样的滤波类型、频率、Q 和增益，不保证得到相同系数或频响。取消 ±12 dB 的输入限制不会消除这些算法差异。** 本轮只做离线分析，没有连接、写入设备，也没有改动现有滤波算法或预设。

## 方法与来源

对比对象是本地官方 APK `2.25.0c-260813ai`（versionCode 102034），来源 `https://download.moondroplab.com/moondroplink/android-release.apk`，APK SHA-256 为 `04756b49acfea523758d86101c96c1824b7b209ae3a8836c07837088e795d2d5`。不是对所有 App 版本作保证。

确认 Java 的 Freeman3 保存路径后，用 Unicorn 执行 APK 内 `libcxaudiodsplib_embca_jni.so` 的实际 ARM64 函数 `CxAudioConvertEqParams2Coeffs`，没有用第三方公式替代官方函数。输入按 Java → JNI 的字段布局和截断规则打包，输出保留原始字节。APK 成员与本地 ELF 逐字节一致。静态路径、结构与版本依据见[参数及原生路径记录](../../evidence/android-eq-path-notes.md)。

模拟器执行官方设计、float32 处理和固定点转换指令；外部 `pow`、`sin/cos`、`log` 等 libm 调用桥接到主机 Python `math`，float32 接口会再舍入至 float32。因此这不是运行 Android UI 后抓取设备回包，也不能保证与物理 Android 上 Bionic libm 的每个末位完全相同。下面接近 1 dB 乃至数 dB 的形状差异，有原生指令路径的算法差异佐证，不能解释成单纯的末位误差。

对每个样本，先按官方输出的动态 Gain 字段正确还原系数，再计算两边 20 Hz–20 kHz 的频响差；不把整体 `output_gain_db` 的音量差混入比较。频响是数学计算，不是模拟回录测量。

## 范围与结果

覆盖峰值、低架、高架，多个频率和 Q，包含 Q=0.8 等取整差异案例，以及现有 Kadenz 预设的四个滤波器。采样率为 44.1、48、96、192、384 kHz，总共 1355 个样本。

- 1300 个样本两边都可计算和表示；其中 49 个在考虑 Gain 缩放后归一化系数完全相同，包括 15 个零增益直通控制样本。
- 官方转换函数有 3 个样本返回非零状态；对应 Java 包装会返回 null。这些没有当作有效频响参与比较。
- 本工具有 52 个样本的固定 Q22 系数超出 24 位范围；它们同样没有当作可写入的工具结果参与频响比较。
- 可比较样本的最大曲线差约 5.974 dB，出现在接近奈奎斯特频率的峰值滤波设置。不是所有实际调音都会出现这么大的差异。

具有代表性的 48 kHz 样本如下。“最大曲线差”是整个比较频带内的差值，不是标称中心增益差。

| 两边相同的输入 | 最大曲线差 / dB | 说明 |
| --- | ---: | --- |
| 峰值，1 kHz，Q=1，+3 dB | 0.00457 | 中心都约 +3 dB，曲线宽度略有差别 |
| 峰值，10 kHz，Q=1，+6 dB | 0.96037 | 中心都约 +6 dB，周围频段明显不同 |
| 峰值，20 kHz，Q=1，+6 dB | 5.04423 | 高频带宽定义的差异显著 |
| 低架，1 kHz，Q=1，−6 dB | 1.13645 | 转折形状不同 |
| 高架，1 kHz，Q=1，−6 dB | 1.13647 | 转折形状不同 |
| 高架，1 kHz，Q=1，+3 dB | 无可写入的本工具结果 | 官方动态 Gain=4 可编码，本工具固定 Q22 溢出 |

例如峰值 1 kHz、Q=1、+3 dB、48 kHz：

```text
官方：[4284636, -7882656, 3666039, 7882656, -3756371]，Gain=3
工具：[4284373, -7883920, 3667577, 7883920, -3757646]，Gain=3
```

它们的中心增益都接近 +3 dB，但整条曲线并非逐点相同。因此“两个地方都是 +3 dB”不代表整个滤波器的效果相同。

## 原因

1. **峰值滤波器的 Q 处理不同。** 官方先把 Q 转成 float32 的 octave bandwidth，再用包含 `w/sin(w)` 修正项的带宽公式；工具直接使用固定 Q 的 `sin(w)/(2Q)`。低频相近，高频差异变大。即便两边有效 Q 完全一样，仍然存在这个差异。
2. **架式定义不同。** 官方使用 Q 型架式，工具固定 S=1。工具架式标签 Q=1 与官方 Q=1 不是同一种转折斜率。
3. **参数取整不同。** 官方将 `Q×256` 向零截断；工具四舍五入。Q=0.8 分别变成 204/256 和 205/256。
4. **系数精度和缩放不同。** 官方先使用 float32，再动态选择系数缩放；工具主要用 Python double 计算后固定 Q22。官方输出 Gain=3 才对应 Q22，Gain=4 对应 Q21，24 位模式的统一还原尺度是 `2^(25−Gain)`。原始整数不同不一定表示频响不同，所以比较已先归一化。

官方动态缩放也说明：此前的整体增益和滤波器范围调查，只约束本工具当前固定 Gain=3 的实现路径，不能当作整个设备或官方 App 的绝对能力边界。

## 对现有预设的影响

对现有 `kadenz-death-metal-structure-v1.json` 的四个滤波器，在相同参数下按官方函数与本工具分别计算，滤波部分最大曲线差为：

| 采样率 / Hz | 最大差 / dB |
| ---: | ---: |
| 44100 | 0.04317 |
| 48000 | 0.03657 |
| 96000 | 0.01425 |
| 192000 | 0.05969 |
| 384000 | 0.05509 |

这份预设的差异较小，不能推广到其他高频或架式设置；本次没有判断其差异是否可听。三份现有预设和设备写入数据均保持不变。
