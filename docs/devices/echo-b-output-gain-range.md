# ECHO-B 整体输出数字增益范围

调查日期：2026-10-30。本次连接 USB `35d8:149b` 的 ECHO-B，验证当前运行系数的临时写入与读回。整体增益字段命名为 `output_gain_db`，与滤波器内的 `gain_db` 区分。

## 结果与边界

当前实现使用第 9 段 `[B0, 0, 0, 0, 0]`，系数为有符号 24 位 Q22，线性增益为 `B0 / 2^22`，正增益方向的非零系数为 `1…8388607`。因此这条单段实现的非零增益表示范围为：

```text
最小：20 × log10(1 / 4194304)       = −132.45319809215172 dB
最大：20 × log10(8388607 / 4194304) =   +6.020598877840829 dB
```

两个端点均在本机临时写入、ACK 确认并逐字节读回；0 系数静音和中间测试值也通过。软件据此允许 `output_gain_db` 在上述闭区间取值。输入支持小数，实际增益取决于 Q22 舍入；接近下限时步进很粗，不能将极低电平的任意小数理解为精确可实现。静音对应零系数，不用有限 dB 值表达。

这不是整个 DSP 的所有可能增益路径或模拟增益档位的极限；没有探索多段级联、不同缩放字段或硬件模拟增益。正增益不提高耳放的最大输出功率。满幅信号再放大会产生削波风险；软件提示组合频响超过 0 dB，不会自动修改用户增益。

后续[官方计算库对比](echo-b-android-eq-comparison.md)已确认官方原生函数会动态选择 Gain 缩放字段。本页的范围仍仅对应本工具当前固定 Gain=3 的单系数整体增益实现，不是整个芯片的绝对增益极限。

## 探测器与恢复

探测器只接受第 8 段直通、第 9 段为非正纯增益的起始状态。运行前需采集模式并确认是自定义模式，且由 Python 的 `preset.device_lock()` 持锁调用；它不会替代日常预设流程。`SIGINT` / `SIGTERM` 会请求恢复，ACK 不确定时不重发测试写入。如果第 9 段恢复读回失败，保留第 8 段静音，不恢复有声输出。

若同一调查确实需要从保存的备份恢复，在仓库根目录运行以下持锁流程，并将路径替换为该次备份。恢复会先静音第 8 段，再按第 9、8 段顺序恢复及读回；不会保存闪存：

```python
import sys
import subprocess
sys.path.insert(0, 'tools')
import preset

backup = 'runs/该次调查/original-bands-8-9.bin'
with preset.device_lock():
    subprocess.run(['bin/echo_gain_probe', 'restore', backup], check=True)
```

[故障注入测试](../../tools/test_echo_gain_probe.c)覆盖正常流程、初始读取失败、备份已存在、测试 ACK 失败、读回不符、中断、第 9 段恢复失败后保持静音及后续恢复。硬件断开、掉电、强制杀进程不能由信号处理保证恢复，应保留备份并根据实际设备状态处理。
