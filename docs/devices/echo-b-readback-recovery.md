# ECHO-B 读取重试与恢复

设备是否已写入，须结合操作阶段、保存 ACK 和读回结果判断。写后读取失败不等于配置未生效。

## 错误与处理

| 错误 | 含义 | 处理 |
| --- | --- | --- |
| `0xe00002e2` | IOKit `kIOReturnNotPermitted` | 检查设备访问权限，不自动重试 |
| `0xe00002d8` | IOKit `kIOReturnNotReady` | 有限重试读取，不重新发送写入 |
| `0x10000003` | Mach `MACH_SEND_INVALID_DEST`，通信目标失效 | 结束失效探测进程，重新枚举并打开设备，只重试查询和复核 |
| 其他 I/O 错误或非法查询回包 | 不能归为暂未就绪 | 停止，检查状态和原始诊断 |

保存 ACK 完整后出现上述可恢复读取错误，会自动重新连接／读取，并核对本次写入的原计划。恢复次数耗尽后仍保持 `saved_unverified`；可使用 `python3 tools/dac.py verify RUN_DIR` 再做只读复核。不要为恢复读取而重复执行 `apply`。

## 重试规则

- 原生探测器仅重试 GET_REPORT：最多 20 次，间隔 50 ms；不重新发送查询请求。
- Python 管理层在退出码 4（NotReady 耗尽）或 5（通信目标失效）时重新启动只读采集。每段元数据／系数采集最多 3 次，退避 0.25 / 0.5 秒，每进程超时 20 秒；错误类型交替也不增加总次数。每次都新建 HID 管理器、重新枚举唯一设备、打开新连接并从头查询，不拼接失败采集的半截结果。
- 仅在已经遇到通信目标失效、进入重连后，允许设备重新枚举期间暂时不存在（退出码 6）在同一次数上限内等待；初次就不存在、发现多个匹配设备或参数错误均立即停止。
- 写入器对同一操作的 ACK 最多轮询 100 次，间隔 10 ms；标识不匹配的回包在该窗口内过滤。匹配但返回错误的 ACK 会立即失败；不重发可能已生效的写入命令，写入进程超时 120 秒。
- 权限错误和其他 I/O 错误立即停止；非法查询回包不重试，ACK 等待不扩大既定窗口。
- 即使连接恢复，模式、元数据和当前量化系数也必须全部匹配原计划才算成功。恢复过程中不重新编译历史计划，不调用写入器，不发送 EQ 或保存命令。

## 状态与证据

`status.json`、`events.jsonl` 和终端阶段提示区分 `not_written`、`write_uncertain`、`saved_unverified`、`saved_verified`。成功需要完整保存 ACK 与匹配的读回。

每次读取尝试和诊断单独保存，成功后生成标准采集文件。`verify` 校验保存计划的完整性，按系数直接比对，并在 `checks/` 创建独立结果；不重新计算 EQ、不写入、不覆盖源记录。

状态记录包含重连次数、最后的读取错误，以及恢复后是否通过完整验证。网页在操作期间显示“正在重新连接”等进度，通过后更新为 `saved_verified`／`readback_verified`；失败或不匹配不会显示成功。网页完成操作后仍低频读取服务端状态文件，以同步后台只读复核结果；这些 HTTP 查询不访问 USB。

`apply` 与 `verify` 使用协作锁。外部 App、底层程序、断开设备和强制终止不受该锁完全保护，也不能保证自动回滚。

状态与完整操作步骤见[操作指南](../operations.md)。实现与模拟故障覆盖见[探测器](../../tools/echo_probe.c)、[写入器](../../tools/echo_apply_plan.c)、[流程测试](../../tools/test_workflow.py)和[原生测试](../../tools/test_echo_probe.c)。原始设备操作证据由各次操作写入 `runs/`。
